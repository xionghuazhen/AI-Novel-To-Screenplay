# Demo 演讲词 — AI Novel To Screenplay

> 预计时长：3-4 分钟 | 建议配合屏幕录制边讲边演示

---

## 一、开场（30秒）

大家好，我今天演示的项目是 **AI Novel To Screenplay —— AI 小说转剧本工具**。

网文作者想把小说改编成影视剧本，传统方式需要编剧手工做六件事：整理人物、拆分场景、提炼剧情、重写对白、格式化剧本、还要检查一致性，过程耗时且成本高。

这个项目做的事情很简单：**把多章节小说粘贴进来，AI 自动输出一份结构化 YAML 剧本**，包含角色设定、场景拆分、影视化对白、镜头建议、质量评分，以及一致性检查报告。

下面我来演示完整流程。

---

## 二、输入与章节识别（40秒）

打开浏览器，访问 localhost:3000，这是我们的前端界面。左边是输入区，右边是输出区。

我们可以直接粘贴小说文本，也可以上传 txt 或 md 文件。这里我点一下「示例」按钮，加载一段 3 章的仙侠小说。

可以看到，系统自动检测到了 3 个章节标记，字数是 1100 字，下面还显示了预计处理耗时大约 22 秒。

这里有一个贴心设计：输入内容 3 秒后会自动保存到浏览器本地存储，即使不小心关掉页面，回来也能恢复草稿。

现在点「开始转换」，或者按 Ctrl+Enter 快捷键提交。

---

## 三、Agent 工作流处理（40秒）

转换开始后，可以看到底部出现了进度条，显示 6 个 Agent 节点正在顺序执行。

这 6 个 Agent 分别是：
1. **Parse** — 解析小说章节结构
2. **Character** — 提取所有角色及其关系
3. **Plot** — 分析主线、支线和关键冲突
4. **Scene** — 拆分为可拍摄的场景
5. **Dialogue** — 把叙述文字变成人物对白
6. **Assemble** — 组装完整剧本，加上镜头建议和质量评分

每个节点前面的圆圈会依次点亮——✓ 表示完成，◉ 表示正在执行。同时右上角实时显示已经过了多少秒。

这里我重点讲一下性能优化。初始版本每个场景都单独调用一次 LLM，3 章小说就有 29 次调用，要等 6 分钟。后来我们做了批量调用优化，把所有场景的对白合并到一次请求里，同样的输入现在只需要 5 次 LLM 调用，大约 60 到 80 秒，提速了 5 倍。

---

## 四、输出结果展示（50秒）

处理完成，右边出来了结果。我们逐个看三个标签页：

**第一个，「预览」标签**。最上面是剧本标题「重生」和题材分类。往下是角色列表——主角林凡、配角陈伯、反派赵鹏，还标注了每个角色的定位。再下面是 6 个场景卡片。每个场景显示了地点、时间和剧情目标。对白内容里，说话的角色用黄色高亮，带了情感标注。如果一个场景对白很多，点击卡片可以展开看完整版。

**第二个，「YAML」标签**。这就是生成的结构化剧本。可以看到完整的 YAML 格式，包含 characters、scenes、dialogue、camera_notes 等所有字段。这个 YAML 格式是参考影视行业标准设计的，可以导入 Unity Timeline、Unreal Sequencer 或 Final Draft 等工具。右上角有「复制」按钮可以一键复制，还有「下载」按钮导出到本地。

**第三个，「评分」标签**。系统从四个维度对剧本质量打分：结构、对白、节奏、角色一致性，最后给出一个综合分。下面是自动一致性检查——这里显示通过，如果有问题会列出具体的 issue。

## 五、多轮修改（30秒）

剧本生成后不是终点，用户还可以继续修改。在输出区下方有一个修改输入框。

比如说输入一句自然语言指令：「把第一场改成夜晚」，然后点修改。系统会把这条指令发送给后端的 modify 接口，由 Dialogue Agent 根据要求更新剧本内容，几秒钟后新的剧本就出来了。这个功能支持多轮迭代，用户可以反复调整直到满意。

---

## 六、技术架构简述（30秒）

最后简单讲一下技术架构。

整个系统分三层：前端是用 Next.js 14 加 Tailwind CSS 构建的；后端是 Python FastAPI，提供 REST API；核心是 **LangGraph 编排的 6 节点 Agent 工作流**。

LLM 层做了统一 Provider 封装，通过环境变量就能在 Claude、GPT、DeepSeek、Qwen 四种模型之间一键切换，不需要改一行代码。

其他加分特性还包括：RAG 跨会话记忆——相同小说的角色信息会被持久化，下次处理新章节时自动注入上下文；Token 优化——关闭了 thinking 模式并做了章节摘要压缩；以及完整的 Schema 文档——包含了 UML 结构图和 Mermaid 关系图。
